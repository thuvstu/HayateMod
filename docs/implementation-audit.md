## 実装済みの補完

### 第1回: §6.2 / §6.4 / A10

- `ContentPipeline`: 解析 → 参照/ルール検証 → 説明文生成検証をCLI/ゲームで共通化。
- `ContentRepository`: 有効なデータと読み込み元を単一スナップショットで公開。
  初回失敗は未準備、再読み込み失敗は既存スナップショット維持。
- `ContentHolder`: 配布JARと設定フォルダからの読み込み。
- reload: 街限定・全プレイヤーを検査・エンカウンター中拒否。
  失敗時は成功表示せず、エンジンも再生成しない。
- YAML: 入れ子の非文字列キー、非有限数、再帰エイリアスを拒否。

### 第2回: 復旧と安全性の補完

- `origin/master` の `10d7767` を作業ブランチへマージ済み。
  欠落していた7クラス、追加の `GroundFinder`、テスト3ファイルが復旧。
  `.gitignore` は上流のルート/モジュール出力だけを除外する定義へ統合。

  mods、flags、時間軸、ドロップ、生活、数値係数、ルールセット等の入れ子も検査。

  読み込み失敗ファイルの上書き禁止、flushした一時ファイルからの原子的置換。
- 存在しないスキル枠へのルーン適用でNPEにならないよう修正。
- テストのContent Packパスを絶対パスへ正規化し、ルート実行時の既存テスト失敗を修正。

詳細な制約・判断・検証方法は [ADR-28](adr/28-safety-and-validation.md)。

## 読み込み元と優先順位

1. `<Fabric config directory>/hayatemod/content/` が存在すれば完全パックとして採用。
2. 開発環境のみ `./content/`、次に `../content/`。
3. Modに同梱された `content/`。

複数パックを部分マージしない。設定パックは正本 `content/` を丸ごとコピーする。
優先パックが壊れていれば下位ソースへ黙って切り替えない。
`ContentHolder.source()` は直近に試したパスではなく、稼働中データのパスを返す。
