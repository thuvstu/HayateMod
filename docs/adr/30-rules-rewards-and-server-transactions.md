# ADR-30: 難易度・報酬・収集シム・サーバー取引の接続

2026-10-09。対象: IMPLEMENTATION.md §5.9–5.10、§5.14–5.15、§7.2、§8.3、V11。
状態: 実装＋core補助検証済み。Fabric全体ビルド・実機検証は未確認。設計書全体の完了宣言ではない。

## 1. 難易度を「解析のみ」から実処理へ

- `Ruleset` に敵HP/DPS、欠片/素材倍率、順序付きtag_overrides、by_idを保持。
- 共通 `RuleResolver`: identity → global/選択ルールのdefaults → global/選択ルールのtags → global/選択ルールのby_id。
  同じ階層では選択ルールが優先。複数タグはYAMLの宣言順で後勝ち。倍率は累乗せず**置換**。
  省略フィールドは継承、明示nullは解析エラー。
- `solommo:global` は任意の予約ID（存在しなければidentity）。`extends_global: false` は継承しない。
  通常パックは global ファイルなし。既存normalは従来通り1倍。
- `solommo:heroic`: HP1.35、DPS1.2、欠片2、素材1.5。`rank:boss` のHPだけ1.5。
- 倍率は有限かつ `(0,100]`、タグの一致先、by_id参照、重複タグを検証。
  by_idが3件を超えたらV11警告。数値上限・V11閾値は初期安全方針。
- `/solommo difficulty` で表示、`/solommo difficulty solommo:heroic` / `solommo:normal` で変更。
  ソロ設計に合わせてワールド共通。全員が街・生存・非観戦・戦闘終了から200tick・エンカウンター外であることを確認。
- 選択IDは既存SaveFilesのバージョン付き原子保存で `hayatemod/difficulty.json` へ。
  保存IDが削除されていればログを残して数値はneutral。削除IDをファイルから勝手に消さない。
- 敵出現時の4倍率をentity tagへ数値スナップショット保存。既存個体のHP/攻撃/報酬を難易度変更やreloadで変更しない。
  スナップショットのない旧個体はneutral。召喚味方には難易度ボーナスを適用しない。
- Content敵/ボス/自然敵のHP、vanilla攻撃/engine攻撃/ボス致死ギミックの与ダメに接続。
  既存wild補正は別レイヤーとして維持。**全攻撃の基礎DPSをEnemyStats値へ再設計したわけではない**。

## 2. 排他的報酬と共通クラフト式

レビューで旧DropHooksが武器ごとに独立抽選していることを確認。§5.10の確率合計制約と不一致だったため修正。

- `LootRoller` の1回の累積確率抽選で装備は最大1個。余り確率はドロップなし。
- ルーンは従来の独立抽選。欠片は装備ドロップの有無にかかわらず付与し、リセットしない。
- 欠片/素材だけ出現時倍率を適用。装備・ルーンの確率を増幅しない。
- 整数化は切り捨て。正の確定欠片は最低1、元が0なら0。素材は0になり得る。
- 報酬は1行4096個までに制限し、ドロップは64以下へ分割。素材範囲と欠片の元データも0〜4096を検査。
- `CraftRules` をゲームとシムで共有。既存の `IL*3` 素材＋unique欠片10、分解素材式を維持。
  タグ素材を使う新しいレシピ体系・アフィックス生成はまだ別の残課題。

## 3. 複数装備の収集シミュレーター

```sh
bash gradlew :tools:collectionSim \
  -PcliArgs="solommo:flame_golem solommo:normal 15 solommo:ember_branch 42 1000 1000"
# enemy / ruleset / 1周分数 / カンマ区切り対象ID / seed / 試行数 / 最大周回
```

- 実処理と同じLootRoller・RuleResolver・CraftRulesを利用。
- 方針: 指定順で未所持品を交換、交換できなければクラフト。重複は既存分解式で素材＋欠片2へ。
  通貨は取得・支出を追跡。直ドロップでリセットしない。市場・移動・拾い忘れ・バッグ容量はモデル外。
- 平均/p50/p95/最大、未完了試行数、確率に依存しない保守的な入手上限を出す。
  到達不能/試行打ち切りを成功と数えない。完成試行だけの平均には偏りの注意表示。
- 最大1000万ロール。固定seedで再現可能。1周時間は**呼び出し側の仮定/実測入力**でありシムの実測値ではない。

seed42・1000試行・最大1000周・仮定15分/周:

| 内容 | 平均周回 | p95周回 | 保守的確定上限 | 打ち切り |
|---|---:|---:|---:|---:|
| normal flame_golem / ember_branch | 8.279 | 12 | 12 | 0 |
| heroic flame_golem / ember_branch | 5.054 | 6 | 6 | 0 |
| normal slag_colossus / cinder_aegis＋slag_cleaver | 14.286 | 24 | 32 | 0 |

最初の条件は平均124.19分・上限180分。複数装備条件の上限は480分であり、
「全収集も3時間以内」とは主張しない。実機TTKを測って次に調整するための結果。

## 4. C2S/コマンド共通の取引・ビルド変更防御

レビューで次の問題を発見し修正:

- MarketBuy/Sellのpacket countに負数/0/巨大値を渡せた → サーバーで1〜64を検査。
- 市場在庫不足でも購入できた → 在庫を照合して拒否。
- 大量売買を開始時の単価で一括計算し裁定が可能 → `TradeRules` で1個ごとの限界価格を計算。
  買いはceil、売りは返品後在庫のbidをfloor。1取引4096エメラルド上限。
  同じ在庫経路を往復しても通貨が増えないことを固定seedで1万組検査。
- 買値/売値表示を次の1個の価格へ合わせ、まとめ買いでは単価変動する旨を表示。
- 街判定がXZ座標だけ → オーバーワールド、街の高度±32も検査。死亡/観戦/戦闘中の街サービスを拒否。
- 工房・分解・市場・交換・ソケット・キーストーン・ロードアウト保存/適用へ街ガードを接続。
- ルーンの品種を見ずに任意のRUNE品を消費していた → `RUNE_ID`一致の品だけ消費。
  同じソケット値への再設定は無消費no-opにしてルーン増殖を防止。
- LoadoutSaveの無制限名/件数 → 32文字、制御文字不可、新規16件まで。
- インベントリ満杯で取得物が消えていた → 残りを足元へドロップする共通giveOrDropへ。
  作成不能な武器・交換品は費用を消費する前に拒否。
- 不明なTavernEnterを既定ダンジョンに置き換えていた → 不正IDを拒否。

NPC個体との近接距離/開いた画面のセッションID/全C2Sのレート制限は未追加。
街ゲートだけで§7.2全項目が完了したとは扱わない。
