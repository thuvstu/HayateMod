# ADR-32: 効果の順序と同期ダメージ境界の因果情報

日付: 2026-10-09 / 状態: 実装・core検証済み、Fabricビルド・実機受入未完了。
対象: IMPLEMENTATION.md §6.6 / §6.4 / A1。設計全体の完成宣言ではない。

## 決定: 順序

- EffectDefに `id` / `source` / `priority` を追加。既存コンストラクターと省略YAMLを維持する。
- YAMLで指定可能なのは `id` と `priority`。priorityは整数[-1000,1000]、既定0、**小さい方が先**。
  sourceはローダーが `weapon:<content-id>` / `rune:<content-id>` を設定し、著者の指定は拒否する。
- 省略IDは武器 `skills.<slot>/<8桁index>`、ルーン `effects/<8桁index>`。
  同一武器（スロットをまたぐ）またはルーン内のID重複を拒否。
  明示IDは空白不可、128文字以内、英数と `_ . / : -` のトークン。
  自動IDは配列位置に依存するため、並べ替えに耐えるIDが必要なら明示する。
- 同一トリガー評価集合内で priority → source種別（weapon/rune/その他）→ source文字列 →
  effect ID → slot → 配列位置。対象の同順位はUUID順。既定で武器→ルーンを維持する。
- dispatch/timerは全スロットの候補を集めてからソートし、**評価予算の消費前**に順序を確定する。
  chanceもこの順で評価。採用された全条件はアクションより前に判定する。
- delay/repeatは親の順序キーを保持。予約は due tick → 効果キー → 予約連番。
  過去の期限が優先度より先。同期限同キーの汎用予約はFIFO。
- 別のネイティブイベント、別対象への個別命中、tick全体を並べ替えるものではない。
  死亡通知内は従来のkill→death順を保持する。
- SkillSnapshot、説明の各スロット/ルーン内、reportの順序表示に同じメタデータを使用。
  任意のEffectTraceリスナーでtick/trigger/skill/source/id/priority/owner/target/depth/historyを取得可能。
  未設定時にtraceは生成しない。Modログへの配線、遅延再開専用traceは未実装。

## 決定: 同期ダメージ境界

- WorldAdapterにCastContext付きダメージ/雷/爆発のオーバーロードを追加。
  旧アダプターは既定委譲で互換だが、再入する実装は文脈付きポートを実装する必要がある。
- 通常命中はその文脈を渡す。strike/lightning/explosionは履歴に自分のアクション名を加え、
  深度を1増加。絶対上限3に達した文脈から新たなダメージprocを生成しない。
- on_kill/on_damaged/on_deathは受け取った深度・履歴をゼロへ戻さない。
  撃破は原因の受理済みカード/BuildModsを優先し、持ち替えで帰属を変更しない。
  被弾・死亡のカード/owner/BuildModsは防御側のものに置き換え、因果履歴だけを継承する。
- McAdapterの単一booleanを、対象UUID付き・スレッド局所のDamageScopeへ置き換える。
  入れ子や例外でもfinallyで親へ復元し、別対象の偶発的な通知へ原因を誤適用しない。
  エンジンダメージでは近接置換へ戻らないが、被弾/シールド判定/second wind経路には戻す。
  全量シールド吸収はon_damaged対象外。入れ子で既に死亡したプレイヤーへの親ヒットは中止。
- 防御側と原因不明の撃破でのルーン受動効果は、カードのprimary（なければ先頭slot）へ一度だけマージ。
  全slotにマージして3重発火させない。発動済みsnapshotには重ねて追加しない。
- 死亡通知は弱参照の**オブジェクト同一性**集合で重複排除。UUIDだけでは復活後も抑止するため不採用。
  同じUUIDを持つ新しいプレイヤー実体は別の死亡を通知できる。環境死でもon_deathへ到達する。
- 爆発の `level.explode` は独自範囲ダメージに加えて無帰属ダメージも生むため廃止。
  ownerのdimensionで視覚・音・ノックバックを明示し、UUID順で独自ダメージだけを適用。
  ブロック破壊はしない。旧来の二重ダメージ/バニラ爆発の減衰とは挙動が変わるため実機比較が必要。

## 未完了と実機受入手順

1. `:core:test :tools:validateContent :mod:build` を実行可能な環境で確認する。
2. 投射後に武器/ルーンを持ち替えて撃破し、旧snapshotの効果だけが一度発火すること。
3. 反撃→雷→撃破/死亡を発生させ、深度/予算と帰属、shield/second windを照合する。
4. 同一実体の重複死亡通知を抑止し、復活後の再死亡と環境死は通知すること。
5. overworld以外で爆発し、1回分のダメージ・ノックバック・視覚/音・非破壊を確認する。
6. 炎上/毒など後続tickのバニラDOT、召喚NPCの攻撃、外部Modの非同期/別イベント経路は
   この同期scopeだけでは文脈を保持しない。帰属の永続化・寿命・重複排除を別途設計/実装する。
7. join/timer等のその他受動ルーン配線、全攻撃経路の統一、NPC戦闘シムも残る。
